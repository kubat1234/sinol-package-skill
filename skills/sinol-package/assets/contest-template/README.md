# Contest template

[SIO2](https://github.com/sio2project/oioioi) contest, packages built with
[sinol-make](https://github.com/sio2project/sinol-make).

## Setup

**Use this template**. The first push puts the repository name into the
statement templates (`\konkurs`, `\signature`). Then clone and:

```sh
pip install --user sinol-make        # >= 1.9.15
# pipx install sinol-make
python3 contest.py init --id <contest-id> --name "<Contest Name>"   # commit hook + name
```

## Claude Code

Opening the repository in Claude Code offers to install the
[sinol-package](https://github.com/kubat1234/sinol-package-skill) skill. Manually:
`/plugin marketplace add kubat1234/sinol-package-skill`, then
`/plugin install sinol-package@sinol-package`.
The repository turns on auto-update for it (`.claude/settings.json`): new
versions install in the background and load in the next session. Update now:
`claude plugin update sinol-package@sinol-package`.

## New package

```sh
sinol-make init abc -t _templates std     # std | chk (checker) | lib (library) | soc (interactive)
```

## sinol-gen

Tests are generated by `prog/abcingen.cpp` with
[sinol-gen](https://github.com/kubat1234/sinol-gen) (`prog/gen.h`). Docs:
`docs/guide.md` in its repository.

## Commands

In a package directory (`sinol-make -h`, `sinol-make <command> -h` for help):

```sh
sinol-make gen       # generate tests (ingen + model solution)
sinol-make inwer     # check tests with the verifier
sinol-make run       # run solutions; -a saves expected scores to config.yml
sinol-make verify    # full check: gen + inwer + run against expected scores
sinol-make doc       # compile the statement
sinol-make export --export-ocen   # package archive for SIO2 + ocen tests
```

In the repository root:

```sh
python3 contest.py lint                 # statement vs config, TODOs, old gen.h, ...
python3 contest.py export-all           # export --export-ocen, archives in _export/
python3 contest.py update gen [abc|all] # newer gen.h into _templates (+ packages, only if their tests stay the same)
python3 contest.py update tools         # contest.py, .github/, .githooks/, .claude/, .gitignore, README.md
python3 contest.py update templates [abc|all] # _templates/ (+ shared files of packages) from contest-template main (keeps the contest name and logo)
python3 contest.py logo logo.png        # new logo in _templates and all packages
```

WSL: add `-T time` to `run` / `verify` (no sio2jail).

**Release**: every push updates the [`tasks` release](../../releases/tasks)
(statement, package, ocen tests or dlazaw.zip per task). State: `!todo` / `!ver` / `!done`
in a commit title; `!rebuild-abc` / `!rebuild-*`.

## config.yml

- `sinol_expected_scores` is written by `run -a` and is what `verify`
  compares against. `run -a` rewrites the whole file, so comments in
  `config.yml` are lost.
- `subtask_dependencies`: a group's points count only if the listed groups
  also pass, e.g. `3: [1, 2]`. Not transitive, so list all of them.

## Conventions

- `prog/`: `abc.cpp` model, `abc2.cpp` correct, `abcs1.cpp` slow, `abcb1.cpp` wrong
- Tests: `abc0.in` statement example, `abc1ocen.in` … ocen (public) tests,
  `abc1a.in`, `abc1b.in`, `abc2a.in` … groups.
- `abc/dlazaw/` (optional): files for contestants, automatically packed and
  published to them (instead of the ocen tests).
- Commits: `abc: summary` / `*: summary`, ≤ 50 chars.
